================================================================================
                        SIHANDAL V2 - CODEBASE EXPLANATION
================================================================================

Sihandal (Sistem Informasi Keuangan Daerah) is a Regional Financial Information
System — a government financial management web application for Indonesian local/
regional government agencies (OPD — Organisasi Perangkat Daerah).

                              KEY FEATURES
================================================================================

  Module                 Purpose
  --------------------   ------------------------------------------------
  Dashboard              Overview with charts (bar, donut, radial), stat cards
  OPD Management         View all government departments, drill into details
  Sumber Dana            Fund source management per OPD with pagu tracking
  Rekening Kas           Cash account management (kas, pendapatan, belanja)
  Program & Kegiatan     Activity/program budget tracking with codes
  Penerimaan             Revenue recording with target vs realization
  Pengeluaran            Expenditure tracking with budget vs actual
  Posisi Kas             Cash position snapshots (saldo_awal +/- changes)
  Permintaan Dana        Fund request workflow (draft -> submit -> approve/reject)
  Persetujuan            Approval/rejection of pending fund requests
  Transfer Dana          Fund transfer tracking with status workflow
  Laporan                Read-only reports: penerimaan, pengeluaran, posisi kas
  User Management        Admin-only user CRUD with role assignment
  Data Import            CLI command to import budget data from CSV

================================================================================
                      FUND REQUEST WORKFLOW (Core Logic)
================================================================================

  1. Draft:       OPD creates a PermintaanDana with amount, fund source, purpose
  2. Submit:      Validates available budget, calls SumberDana::commit() to
                  temporarily lock funds
  3. Pending:     Awaits admin/approver action
  4. Approve:     Calls SumberDana::realize() to convert committed to realized
  5. Reject:      Calls SumberDana::releaseCommit() to free up committed funds

================================================================================
                      DATABASE TABLES & RELATIONSHIPS
================================================================================

  users
    role (enum: 'admin', 'opd')
    opd_id (FK -> opds, nullable)
    hasMany -> persetujuans

  opds
    kode (unique)
    total_pagu (decimal 18,2)
    hasMany -> sumberDanas, programs, penerimaans, pengeluarans,
              permintaanDanas, transferDanas, posisiKas

  sumber_danas
    opd_id (FK -> opds)
    nama_sumber_dana, pagu, realisasi, dana_di_commit, persentase
    Methods: availablePagu(), commit(), releaseCommit(), realize()

  programs
    opd_id (FK -> opds)
    kode_kegiatan, nama_kegiatan, kode/sub sub-kegiatan
    sumber_dana (string), pagu, realisasi, persentase

  rekenings
    kode (unique), nama, tipe ('kas'|'non-kas'|'pendapatan'|'belanja'), saldo

  penerimaans
    opd_id (FK -> opds), rekening_id (FK -> rekenings, nullable)
    kode_sumber_dana, nama_sumber_dana, target, realisasi, persentase
    tanggal, keterangan

  pengeluarans
    opd_id (FK -> opds), rekening_id (FK -> rekenings, nullable)
    kode_kegiatan, nama_kegiatan, sumber_dana (string)
    anggaran, realisasi, persentase, tanggal, keterangan

  permintaan_danas
    nomor_permintaan (unique, e.g. "PD-0001/2026")
    opd_id (FK -> opds), sumber_dana_id (FK -> sumber_danas, nullable)
    jumlah, sumber_dana (string), keperluan
    status (enum: 'draft'|'menunggu'|'disetujui'|'ditolak')
    tanggal, tanggal_disetujui, catatan

  persetujuans
    permintaan_dana_id (FK -> permintaan_danas)
    user_id (FK -> users)
    keputusan ('disetujui'|'ditolak'), catatan

  transfer_danas
    nomor_transfer (unique, e.g. "TF-0001/2026")
    opd_id (FK -> opds), jumlah, sumber_dana (string), keterangan
    status (enum: 'draft'|'diproses'|'selesai'|'gagal')
    tanggal, tanggal_selesai

  posisi_kas
    opd_id (FK -> opds), rekening_id (FK -> rekenings)
    tanggal, saldo_awal, penerimaan, pengeluaran, saldo_akhir

================================================================================
                           ARCHITECTURE PATTERNS
================================================================================

  1. OPD-Scoped Multi-Tenancy
     The base Controller class provides three helper methods:
       - applyOpdScope()     — filters queries to user's OPD (admins see all)
       - userOpds()          — returns user's OPD (or all for admins)
       - authorizeOpdRecord()— prevents cross-OPD access (returns 403)
     Every controller uses these consistently.

  2. Two-Role Authorization
     - Admin:  sees all data, manages users, approves/rejects fund requests
     - OPD:    sees only own OPD data, creates/edits own records, submits requests

  3. Computed Fields
     - persentase auto-computed on every store/update (realisasi / target or pagu)
     - saldo_akhir auto-computed (saldo_awal + penerimaan - pengeluaran)
     - nomor_permintaan / nomor_transfer auto-generated with sequential numbering

  4. Form Request with Shared Traits
     ValidatesPermintaanDana trait shared between store and update requests,
     ensuring consistent business rules including cross-OPD validation.

  5. Reusable Blade Component Library (23 components)
     stat-card, chart-card, status-badge, filter-bar, page-header,
     progress-card, alert, modal, timeline, priority-badge, text-input,
     input-label, input-error, dropdown, buttons, etc.

  6. Custom Tailwind CSS 4 Theme
     Semantic color tokens: primary blue (#0F4C81), surface gray (#F5F7FB),
     success/warning/danger/info palettes, Instrument Sans font.

  7. Server-Rendered SPA-Like Experience
     Traditional Laravel Blade + Alpine.js — no separate frontend framework,
     keeps things simple while feeling responsive.

  8. Separate CRUD and Report Controllers
     Each data module has both a CRUD controller and a read-only report
     controller, keeping read paths clean.

  9. CSV Import for Initial Data
     ImportSumberDana command handles bulk import of government budget data,
     creating OPDs, rekenings, sumber danas, and programs in one transaction.
